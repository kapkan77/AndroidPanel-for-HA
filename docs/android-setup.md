# Установка Android-панели из конструктора HA

Это предварительная версия мастера. Его логика проверена автоматическими тестами
на имитации Android; полный сценарий после заводского сброса ещё требует проверки
на настоящей панели. Ничего не устанавливается автоматически при добавлении интеграции.

## Подготовка после сброса

1. Завершите начальную настройку Android и подключите Ethernet или Wi-Fi.
2. Откройте сведения об устройстве и включите режим разработчика. На большинстве
   прошивок для этого несколько раз нажимают «Номер сборки»; у YC-SM41P пункт может
   называться иначе в зависимости от прошивки.
3. Включите отладку Android и **отладку по сети / Network ADB**.
4. Посмотрите IP-адрес панели. Если порт отладки не указан отдельно, обычно используется `5555`.
5. Убедитесь, что HA видит эту локальную сеть. При настройке полного киоска не
   добавляйте личные Android-аккаунты: они могут помешать назначению владельца.

Поддерживается обычный TCP ADB, включая подтверждение RSA-ключа на экране Android.
Режим **Wireless debugging с кодом сопряжения** в этот выпуск не входит.
Если прошивка разрешает ADB только через USB, сначала потребуется её штатная
процедура включения сетевой отладки — HA не может подключиться к выключенному ADB.

## Установка интеграции в HA

1. Откройте **Настройки → Маркетплейс → Добавить по ссылке**.
2. Укажите `https://github.com/kapkan77/AndroidPanel-for-HA`, тип **Интеграция**.
3. Самостоятельно прочитайте и примите предупреждения маркетплейса, если он их покажет.
4. Установите **Home Panel**, затем перезапустите HA.
5. Добавьте **Home Panel** через **Настройки → Устройства и службы**.
6. Полностью обновите страницу браузера.

В общий каталог проект пока не включён; искать его без добавления ссылки не нужно.

## Подготовка интерфейса

1. Создайте представление дашборда с типом **Панель (одна карточка)**.
2. Добавьте карточку **Панель комнаты** и откройте её конструктор.
3. Выберите шаблон **Климат и комфорт**, назначьте свои устройства и датчики.
4. Примените макет и сохраните карточку HA.
5. Откройте получившееся представление и убедитесь, что его адрес ведёт прямо
   к нужной комнате. Запомните этот полный адрес.

## Установка приложения по IP

1. Снова откройте конструктор и нажмите сверху **Android-панель**.
2. Введите название, IP и порт ADB панели.
3. Укажите полный адрес нужного представления HA. Адрес должен быть доступен
   **с Android-панели**. Логин, пароль и токены в адрес не вставляйте.
4. Для защиты от выхода оставьте флажок **Настроить полный киоск**.
5. Нажмите **Проверить подключение**. До отдельной кнопки установки APK не передаётся.
6. Если Android покажет запрос разрешения отладки, подтвердите его на панели,
   затем при необходимости повторите проверку в HA.
7. Сверьте модель, версию Android, установленное приложение и владельца устройства.
8. Нажмите **Установить приложение и киоск** и дождитесь результата.
9. На Android создайте PIN из **4 цифр** и войдите в HA пользователем панели.
10. Проверьте кнопки и затем самостоятельно перезагрузите панель, чтобы проверить автозапуск.


После успешной установки название, IP, порт и адрес сохраняются в списке панелей
интеграции. Сведения о подключении не входят в шаблоны карточки.

## Как связаны части системы

```mermaid
flowchart LR
    A[Конструктор HA] -->|Проверка и явная установка по ADB| B[Приложение Android]
    B -->|Пользователь создаёт PIN и входит в HA| C[Дашборд комнаты]
    B -->|Домашний экран Android| D[Автозапуск и киоск]
```

## Что выполняется при проверке

Проверка не меняет настройки Android. HA открывает ADB-соединение **только с введённым
IP**, а не сканирует сеть. При первом подключении на HA создаётся собственная пара
RSA-ключей. Android может попросить владельца разрешить этот ключ.

Мастер читает только:

```text
getprop ro.product.model
getprop ro.product.manufacturer
getprop ro.build.version.release
getprop ro.build.version.sdk
getprop ro.serialno
dumpsys device_policy
dumpsys package local.home.hmi
```

Серийный номер нужен, чтобы при установке проверить, что за тем же IP осталось
то же устройство. Он хранится в памяти проверки до пяти минут и не добавляется
в карточку, шаблоны или сохранённый список панелей. Без номера автоматическая
установка останавливается.

## Что выполняется при установке

1. Повторно проверяются устройство, Android и локальный APK с его контрольной суммой.
2. Если выбран полный киоск, а устройство принадлежит другому приложению, мастер
   останавливается до передачи APK.
3. APK из установленной интеграции копируется в `/data/local/tmp/home-panel-kiosk.apk`.
4. Выполняется установка с сохранением данных:

   ```text
   pm install -t -r /data/local/tmp/home-panel-kiosk.apk
   ```

5. Если выбран полный киоск и владельца ещё нет:

   ```text
   dpm set-device-owner local.home.hmi/.PanelAdmin
   ```

   Уже назначенный наш киоск повторно владельцем не назначается. Если Android
   отказывает, мастер сообщает о частичной установке и не удаляет аккаунты.
6. Защищённому получателю приложения передаются **адрес дашборда** и запрос
   включить защиту. Получатель требует системное разрешение `android.permission.DUMP`,
   которое есть у ADB shell и отсутствует у обычных сторонних приложений.
   Сам PIN не передаётся и не заменяется.
7. Выполняется запуск:

   ```text
   am start -n local.home.hmi/.MainActivity --ez refresh_url true
   ```

8. Удаляется только временный APK, созданный мастером. В HA сохраняются название,
   IP, порт, адрес дашборда, установленная версия и время установки.

В мастере нет произвольной командной строки. Перечень команд ограничен кодом
[`provision.py`](../custom_components/hmi_panel/provision.py).

## Автозапуск и дополнительные настройки

После создания PIN приложение в режиме владельца устройства:

| Настройка | Как применяется |
|---|---|
| Автозапуск | Назначает себя домашним экраном Android; дополнительно слушает завершение загрузки |
| Защита от выхода | Включает Lock Task для своего пакета |
| Шторка и системная навигация | Ограничивает их средствами Android и полноэкранным режимом |
| Экран остаётся включённым | Флаг приложения `KEEP_SCREEN_ON` |
| PIN | Создаётся и меняется на Android; хранится там как PBKDF2-SHA256 с солью |
| Адрес интерфейса | Передаётся мастером и хранится в приложении |
| Ночные часы и яркость | Настраиваются в карточке HA; киоск применяет яркость окна |

Если флажок полного киоска выключен, мастер не назначает владельца устройства.
Уже включённая защита существующей копии от этого не выключается.
Настоящую блокировку выхода без режима владельца обещать нельзя.

Отладка по сети после установки **остаётся включённой**, чтобы мастер мог снова
подключиться. ADB даёт расширенный доступ к Android, поэтому его следует держать
в доверенной локальной сети. Классический ADB не обеспечивает шифрование трафика;
PIN и пароль HA этим мастером не передаются.

## Что мастер не выполняет

- Не сбрасывает Android и не прошивает устройство.
- Не удаляет Android-аккаунты или чужого владельца.
- Не удаляет установленное приложение при несовпадении подписи.
- Не очищает его данные, не меняет существующий PIN и не выполняет понижение версии.
- Не вводит учётные данные HA вместо пользователя.
- Не меняет сеть, системные обновления, драйверы, датчик освещённости или политику сертификатов.
- Не перезагружает панель или HA автоматически.

## Хранение данных и права доступа

Проверка и установка доступны только **администратору HA**; это проверяется сервером.
Обычный пользователь настенной панели не может вызвать эти операции.

Список панелей хранится средствами HA в `.storage/hmi_panel.panels`.
Локальная пара ADB-ключей — `.storage/hmi_panel_adbkey` и файл `.pub` рядом.
Приватный ключ создаётся с правами доступа `0600` на Linux.
Эти данные могут входить в резервную копию HA, но в репозиторий или макет не отправляются.
Удаление интеграции не удаляет приложение с Android и не отзывает ранее разрешённый
ADB-ключ на панели. Отозвать разрешения отладки можно в настройках разработчика Android.

## Если установка остановилась

Результат показывает уже выполненные шаги. Приложение может успеть установиться,
даже если назначение владельца или запуск не удались. Сначала снова нажмите
**Проверить подключение**, затем решайте, нужна ли повторная установка.

- Нет соединения: проверьте IP, порт и отладку; после сброса IP мог измениться.
- Нужна авторизация: подтвердите запрос ADB на Android.
- Другой владелец: мастер не удаляет его; требуется решение владельца устройства.
- Владелец не назначается: Android может запрещать это после добавления аккаунтов
  или из-за ограничений прошивки. Автоматический сброс не выполняется.
- Другая подпись APK: обновление поверх такой копии невозможно; мастер сохраняет её данные.
- Браузер HA потерял связь во время установки: это не доказывает, что установка
  отменена. Повторная проверка покажет версию приложения.

## Тот же сценарий отдельным скриптом

Из корня скачанного репозитория, на компьютере с Python:

```text
python -m pip install adb-shell==0.4.4
python scripts/setup_android.py --ip IP_ПАНЕЛИ
python scripts/setup_android.py --ip IP_ПАНЕЛИ --url "АДРЕС_ДАШБОРДА_HA" --install
```

Замените слова-заполнители своими значениями. Первая команда скрипта только
проверяет подключение. Флаг `--install` явно включает установку и настройку
полного киоска. Флаг `--without-device-owner` пропускает назначение владельца.
Ключ скрипта по умолчанию сохраняется в папке `.home-panel` домашнего каталога
пользователя; это отдельный ключ от ключа HA, и Android может запросить новое разрешение.
Скрипт вызывает тот же модуль установки, который использует конструктор.
